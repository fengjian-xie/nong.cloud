# work.nong.cloud 用户工作台

## 定位与账号模型

主体端共用一套工作台框架和业务模块，不按角色复制11套后台。
一个账号可以拥有多个已授权身份；登录一次，在同一会话内切换当前身份。
例如同一人可以既是种植户，又是农服队成员。切换身份不扩大其他身份的数据权限。

本次提供明确标注的**前端演示**，没有真正的短信、微信登录或服务端授权：

- 8个固定示例账号，覆盖11类工作身份、38个业务页面。
- “种植与农服示例账号”拥有种植户和农服队两种身份。
- “采购与流通示例账号”拥有采购商、冷库、加工分拣三种身份。
- 其余示例账号分别展示合作社、农资商、农机手、植保团队、检测机构、子女代办。
- 只有该示例账号已绑定的身份出现在身份切换器。未绑定身份的直接地址显示不可访问。
- 切换身份不重复登录；刷新恢复当前身份；退出清除整个演示账号会话。
- 会话仅包含版本、示例账号编号和当前身份，使用 `sessionStorage` 的 `xiangqiao:work-demo-session:v2`。
- 不采集手机号、密码、身份证或微信凭据，不发送验证码；业务操作保存在当前浏览器的演示日志，不产生真实订单、合同、付款或设备动作。

本机示例身份可被浏览器使用者修改，**不能当作生产鉴权**。管理后台的全角色演示选择器也不是正式角色授权工具。

## 正式版本必须实现的后端边界

账号、经营主体、工作身份需要分开建模：

| 对象 | 含义 |
| --- | --- |
| account | 一个人的登录账号；跨PC与小程序绑定方式由正式登录服务核验 |
| subject | 种植经营者、农服队、合作社、门店、采购企业等经营主体 |
| membership | 某账号与某主体的有效成员关系，包含启用、到期和撤销状态 |
| identity / role | 该成员关系下的工作身份和岗位，可多种，不能自行选择创建授权 |
| grant | 具体地块、订单、家庭代办、字段和操作的授权 |
| session context | 当前账号、当前主体、当前身份；服务端校验后切换 |

正式身份切换接口应返回服务端核验的可用身份列表，并逐次校验租户、主体、角色、对象归属和操作权限。
每一笔写入须保存账号、当前主体、当前身份、对象、时间和审计编号；同一人切换后不得混淆“委托方”和“服务方”。
订单、地块、成本、库存及家庭数据不能因为账号兼任多角色而合并公开。退出、撤销成员关系、撤销家庭授权须在服务端使相关会话/权限失效。
跨标签页和多设备会话、身份撤销期间的未提交表单，以及同一身份绑定多个农服队的选择，也必须在正式端处理。本次固定示例并未实现这些真实关系。

## 构建与部署

```sh
cd admin-web
npm run build -- --mode work-site --base / --outDir /absolute/new/build-directory
```

work-site使用独立入口 `src/work/main.tsx`，不加载运营后台、消费者农场或API文档页。
角色业务模块按需加载，框架、组件和领域模型复用原有实现。
`deploy_work_site.py` 复用经过回滚测试的独立站首装流程。仅接受尚未存在的本站目录及配置；已上线时会拒绝重跑，不可盲目覆盖。
