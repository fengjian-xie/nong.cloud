# 乡桥全栈递归审查 V3

日期：2026-10-06。范围：五站网页、乡桥小程序、管理模块、农事卡关联流程，以及本轮新增的八项产品价值功能。

本报告依据当前仓库和本机演示验证编写，不是线上部署、真实交易、硬件验收、政府认证或完整安全审计证明。此前功能追加已完成原型开发；本次“重新整理”只复查、归纳和提出修正方案，以下新发现尚未修复。

## 一、结论：一套业务底座，多个入口，按证据形成闭环

保留五个网站、一个多身份小程序。角色和区县共用经过验证的业务流程，不为每个角色、每个分中心复制一套后台或数据库逻辑。当前最重要的工作不是继续增加同类页面，而是补齐统一身份、稳定业务ID、可信证据、版本失效和交易账本。

建议业务主线为：

**主体与授权 → 地块与产季 → 原始采集与核验 → 服务及独立验收 → 实物采收批次 → 授权产品履历 → 供货与订单 → 交付反馈 → 帮助受理与整改。**

成本、库存、权限、财务、公开内容和审计贯穿这条主线，但彼此不混为同一状态。“有记录”不能自动推导出“质量合格、已经认证、可供现货、已签约或可融资”。

正式功能名称统一为“产季记录”。“产季痕迹”可作辅助文案，例如“留下一季耕耘的痕迹”，不再作为第二个业务模块名。它是可追溯的事实与备注集合，不是编造的宣传稿；经本人授权的公开介绍是独立输出。

## 二、递归审查方法与停止条件

每个需求递归拆为八层：

1. 目标：谁的问题，完成后有什么可验证结果？
2. 参与者：谁操作、谁负责、谁验收、谁可以看？
3. 对象：关联哪个中心、主体、地块、产季、批次、订单或凭据？
4. 状态：进入条件、退出条件、撤回、驳回及过期如何表达？
5. 依据：原始记录、照片、视频、报告、交接和授权是否齐全？
6. 权限：当前账号、成员关系、身份、委托范围和后台岗位是否有效？
7. 异常：失败、重复、并发、断网、撤销、证据失效、越权怎样处理？
8. 回查：下游是否仍引用旧状态，公开页、消息、成本、库存是否同步失效？

每个叶节点至少检查正常、失败、撤回、重复、并发和越权路径。缺少证据或实现时记录为“待实现/待验证”，不能用成功提示替代。所有本轮发现都有归属、修正方向和验收条件后结束本轮；不宣称通过有限测试就穷尽所有问题。

## 六、身份、多中心和代办的递归边界

一个人可以是种植户，又属于农服队，也可以采购、消费。应区分：

- Account：登录账号。
- Subject：农户、合作社、队伍、商家等业务主体。
- Membership：账号与主体的成员关系，一个账号可有多个。
- IdentityDefinition：产区可配置的身份名称、流程模板、准入标准和模块能力。
- IdentityGrant：审核后授予某成员的实际身份。
- AdminGrant：平台或服务中心管理员岗位，独立于业务身份。
- Delegation：代办对象、操作范围、有效期、证据与撤销状态。

工作上下文应包含Account、Center、Subject、Membership和有效Grant，而不只是“账号+角色”。同一账号属于两个农服队，必须能切换两个不同的主体上下文。修剪、套袋、采收通常可作为农服能力标签；存在不同准入责任时再新增身份，避免无意义拆分。

自然人识别与审核分离规则还需服务端支持：换角色、换同人账号都不能完成自我验收。身份申请不自动授权，目录修改也不直接改变已授权成员。撤销后旧页面、旧会话、导出、文件链接和未执行任务都要重新校验。

平台—区县中心—乡镇服务站可共用系统，但公司/分公司/合作运营主体的法律关系、签约方、售后方、收款商户必须分别登记。中心目录不等于已开通租户或金融商户。跨中心协作以受控委托和数据共享对象表达，不放开另一中心的全部记录。

## 七、记录、产季、批次与公开的对象关系

| 对象 | 稳定关联 | 不可混同 |
| --- | --- | --- |
| RawEvent 原始事件 | 设备ID、事件序号、时间、按键配置版本、原始定位、同步回执 | 按键不是出工人天，定位不是作业质量 |
| Activity 核验农事 | Subject、Plot、Season、来源事件、证据与核验版本 | 买入农资不是实际施用；现场图片不是完整验收 |
| SeasonRecord 产季记录 | Season、核验Activity/Evidence版本、人工备注、编辑与代办授权 | 不能依靠字符串年份猜测产季，冬季作业可能属于下一产季 |
| HarvestBatch 实物批次 | 产季/地块来源、采收时间、称重、分级、交接 | 一个地块可有多次采收，多批货；一个批次也可能经明确规则混合多来源 |
| PublicationRevision 公开版本 | Batch、获准引用的证据版本、Consent、独立审核、发布时间与撤回 | 不能直接把实时私有记录列表当已审核公开内容 |
| ForecastRevision 预测 | Season、起止日期、数量区间、来源、更新时间、可信程度 | 预测不是可售库存，不是已接受供货合同 |
| Offer/Stock 可供/现货 | 已确认货权、库存账本、预留、质量状态、实际时效 | 现有可供量与预测总产量可能不同，必须明确含义 |
| CostSnapshot 成本 | Season/Batch、科目、数量单位、价格日期、证据、缺项和版本 | 未填不能视为0；估算不是结算或会计利润 |

公开投影允许产品、概略产区、适当产季信息、获准公开的作业摘要、实物批次标识和缺项说明。原始GPS、卡号、农户底价、私人成本、家庭资料、商户凭据和未受理投诉不自动公开。精确地点和镜头观看需要独立授权及访问控制。

原始事件不覆盖；纠错追加新的核验版本。公开内容保存批准时的版本依据，必要时转“待复核”或撤回。授权撤销应阻止继续公开访问，但内部记录保留与删除规则另行确定，不能用“删除浏览器缓存”代替。

## 八、主要状态机与上游变更回查

| 流程 | 建议状态 | 下游回查 |
| --- | --- | --- |
| 设备同步 | 设备未同步 → 手机暂存 → 服务端已持久化 → 设备收到确认 | 未持久化不清设备；重复事件不重复计入农事/成本 |
| 农事核验 | 原始/待确认 → 补证 → 待核验 → 已核验 / 驳回 → 更正复核 | 核验撤销使产季摘要、批次履历和报送资料待复核 |
| 作物变更 | 草案 → 照片视频证据 → 审核 → 新版本生效 | 旧成熟预测、供货摘要、公开履历不能静默沿用 |
| 服务作业 | 委托 → 接单 → 作业 → 提交完工 → 独立验收 / 争议 | 验收结果决定可计费用/履约事实，不改写原始事件 |
| 产季记录 | 汇集依据 → 草稿 → 本人确认 → 公开授权 → 独立审核 → 公开版本 | 草稿、代办整理、媒体授权和公开授权是不同动作 |
| 批次履历 | 来源及实物待确认 → 可提交 → 待审核 → 已发布 → 待复核 / 撤回 | 证据、授权、批次来源、质量或地块版本变化触发复核 |
| 库存订单 | 需求 → 确认意向 → 原子预留 → 交接出库 → 完成 / 退货 | 超时释放预留；退货、加工、损耗按账本处理，不直接重写余额 |
| 帮助反馈 | 登记 → 受理 → 分派 → 补证/答复 → 用户确认 → 关闭 / 重开 | 关联订单、批次、中心和整改；客服不自行改账或核验 |
| 第三方报送 | 授权 → 预检 → 提交 → 受理回执 → 外部处理结果 | 本地导出和HTTP成功不等于一品一码审核通过 |
| 财务 | 支付待确认 → 验签确认 → 分账待执行 → 分账结果 → 退款/回退 → 对账 | 幂等、金额守恒、商户范围与原交易关联，普通工作台无执行权限 |

月度供货筛选应按起止窗口与所选月份是否重叠，而不是只看地块旧“预计采收日”。发布后的记录不是下次刷新时自动重算的新内容，更新须产生新版本或明确失效状态。

## 十、本轮发现：按真实上线风险分级

以下P0表示“不得据此开放真实业务”的门槛，不是说当前明确标注的离线原型已经发生线上攻击。P1需在可信业务联调前解决；P2是原型控制和导航缺陷。

| 级别 | 发现及证据 | 修正方向 |
| --- | --- | --- |
| P0 | 仓库后端只有Spring Boot启动类；V1只有accounts/sessions/entities/idempotency/audit_events，未实现新业务Controller/Service。`backend/src/main/java/cn/fuan/platform/Application.java`、`backend/src/main/resources/db/migration/V1__platform.sql` | 先实现身份成员、中心隔离、类型化业务关系与服务端鉴权，再接真实数据；不把服务器历史站点等同本地骨架 |

## 十一、成本、库存、资源与财务专项规则

### 1. 成本和自主定价

生产成本与渠道履约成本分开。先形成实际施用农资、独立验收服务、确认人天和其他生产费用快照，再形成含包装、冷链、配送、售后等的渠道方案。家庭劳动估值单列，不伪装为已支付现金。

每个科目保留数量、单位、行情/凭据来源、日期、确认状态和分摊范围。空白不当0，卡片100元不能每个地块/批次重复扣一次。参考加价×1.35仅为农户议价示例，不是已经核实的特定企业采购规则，也不是强制收购或利润保证。

### 2. 库存共享与分级货源

“尾货”正式模块宜称“分级货源与库存共享”，强调用途、质量、权属和时效，而不是自动认定低等级可加工。B级外观分级不等于不合格，也不等于食用安全已确认。

采收、入库、货主转移、预留、出库、加工消耗、退货和损耗都写账本。一个批次不能同时被冷库、分拣车间和采购商分别记成新增可售货。需求匹配只是候选信息；确认成交才按服务端事务预留，预留过期按规则释放。

### 3. 生产资料一览图与电力信号

资源目录包含位置、主体、能力、联系人授权、可用时间和人工状态。电力设备信号只能作为运营线索：用电不等于正在生产，未用电不等于停业，离线不等于无产能。显示“信号更新时间/离线/待人工确认”，不能直接据电量判断可接单、产量或利润。

镜头、环境传感器、土壤报告与产品检测是不同来源。海拔和面积需保留测绘来源/误差；施肥建议关联报告与专业人员版本，不由按钮数或摄像头画面自动生成处方。

### 4. 支付与分账

按用户提供的“已有服务商号与中心特约商户号”状态设计，但本轮没有接触或验证真实凭据。服务商主账号、中心特约商户、订单收款主体、分账接收方和合同责任分别绑定。

商户开通、策略审核、执行、退款/回退和对账只放管理后台。普通小程序可以在真实支付接入后查看自己的订单支付结果，不显示或配置平台分账能力。模拟金额、按钮点击和本地日志不是实际支付或分账凭据。

## 十二、帮助中心、标准与治理闭环

帮助中心是跨端服务能力，不是另一个复制业务数据的“中台”。统一SupportTicket关联发起账号、有效主体、中心、订单/地块/批次、问题类型、证据、受理人和结果。

种植户可寻求卡片、农事、地块、农资、作业和销售协助；消费者可问认购、镜头、交付和售后；商家可问凭据、供货和验收。子女可按授权代报，但不能代本人同意任何范围的公开或交易。客服能协助登记和转派，不能自行修改农事事实、产品合格状态、库存或资金。

准入与执行标准应版本化为：角色/环节、适用产区、必须资料、执行动作、验收人、量化或凭据标准、异常处理、申诉和留存规则。服务订单引用签约时的标准版本，不能后台改模板就回溯改变旧订单责任。消息从真实业务状态生成，记录发送/失败/已读与关联对象；没有通知通道时诚实标注未发送。

乡桥记录体系优先验证“来源真实、主体明确、过程可查、修改留痕、独立核验、公开有授权”。认证标签的适用范围与有效期独立显示，不宣称所有已记录产品都已取得绿色食品标识。

## 十四、递归回归测试清单

必须追加以下验收，不仅测试按钮可点：

- 地块同名/人员同名不串数据；同人多账号或多身份不得自审；同角色两个主体草稿与订阅分开。
- 跨中心列表、详情、文件、导出、消息和写操作均拒绝越权；撤销后旧会话/页面重试也拒绝。
- 产季显式归属；同地块多季、多次采收、混批来源完整；无来源不生成证明。
- 已发布依据被驳回、授权撤销、地块/批次版本变化后，公开投影失效并保持历史可审计。
- 未知动作、坏缓存、禁用储存、过期版本、重复请求、断网重试不被当作成功。
- 设备事件重传不重复入账，服务端未确认不清设备；GPS失败/边界附近地块不确定保留待确认。
- 供货窗口跨月、跨年能筛选；预测不锁库存，质量隔离不参与候选，分级/单位不得混用。
- 并发预留无超卖，加工/损耗/退货数量平衡；货权与保管位置分开。
- 成本科目区分未知与0；人天、卡费分摊、服务、损耗不重复计费，负收益正常展示，私人成本不公开。
- 反馈只能关联可访问的真实订单/批次；工单受理、答复、用户确认、重开和整改可追溯。
- 支付/分账/退款回调验签、防重放、幂等、金额守恒、商户匹配及对账；本地模拟不能产生真实执行记录。
- 新闻、社交、记录和镜头发布校验归属/授权；第三方结果按回执状态表达，不冒充审核通过。
- Web和小程序同对象、同状态、同权限；微信真机BLE/NFC/地图/通知与Safari实机单独验收。
- 每次发布验证版本、资源路径、深链、原有业务基线、备份与回滚；不得用构建成功代替部署成功。
