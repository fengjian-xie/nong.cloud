# 乡桥全链路本地联调验收 — 2026-10-08

## 结论与验收边界

种植户办卡→独立审批→云端登记、农机手/采购商身份及会员申请、农机服务→种植户验收、库存采购→双方交接、递归下级中心、分账计算计划已实际连接本地PostgreSQL，并跨网页和小程序浏览器预览回读。

**没有完成全部原型模块或生产外部服务上线。** 实物交付、BLE/NFC/GPS验签、微信真机授权、真实支付分账、退款回退对账、摄像头合同、土壤检测、一品一码、动态中心角色、媒体证据变更、产季成本及冷库货权等仍待接通。不把这些边界记为通过，也没有部署到阿里云。

## 递归测试方式

逐个业务节点核对：当前账号/身份/中心→页面路由及按钮→请求协议→服务端权限→状态迁移/版本→事务/外键/唯一性→数据库重新查询→另一方及另一客户端回读；发现问题修复后重跑主链、异常链及既有回归。

使用独立`qa.`账号及新的测试分公司，消费者基础身份申请业务身份后再由独立中心管理员批准。没有导入生产用户或清空旧记录。测试的免费会员、499元收费边界方案、35%计算比例及1.85元采购金额只是测试数据，不是正式定价或支付政策。

## 实测环境

本地网页4199、小程序HTTP预览4201、Java21/SpringBoot接口8080、PostgreSQL16.4端口55439。Flyway V1–V8、39张`xq_`类型化表；运行账号无superuser/建库/建角色权限。历史不可变约束通过尝试修改后回滚验证。

独立未登录Chrome154.0.8037.98与Playwright WebKit26.5。宽度320/390/768/1024/1440/1920，核心页面高度900；手机交互390×844。另测720×450 CSS视口作为200%桌面缩放的布局近似，不是真实浏览器缩放设置。内置浏览器优先检查，但尺寸 override 与实际CSS尺寸不一致，不将其作为精确尺寸证据。

未测试真实Safari27/iPhone/iPad、Android浏览器、Firefox/Edge、微信开发者工具/真机及生产HTTPS环境。

## 修复与复测

| 发现 | 原因 | 修复/复测 |
|---|---|---|
| 320px顶部横向溢出 | 品牌图片和不换行上下文宽度超过内容区 | 窄屏上下排列，保留完整Logo比例；双引擎通过 |
| 768px分账表单溢出及WebKit窄屏标准表单溢出 | Grid子项和select/input固有最小宽度 | label和表单控件显式min-width:0/width:100%/border-box；双引擎通过 |
| 新采购商登录后采购入口不可用 | 基础消费者身份与已批准业务身份按随机id并列排序 | 业务身份优先；根中心管理优先；真实浏览器采购流程通过 |
| 同身份同时采购出现500 | 幂等记录外键KEY SHARE与身份FOR UPDATE锁升级形成死锁；数据库日志已确认 | 改为FOR NO KEY UPDATE，不修改身份键；8轮竞争均一成功一409；无新增死锁日志 |
| 会员、采购、中心及分账原型没有真正API | 只有静态原型/预留表 | 新增V8模型、接口、Web/小程序适配及可执行字段契约；真实回读通过 |
| 卡片100元报价被通用费用字段误标为会员费用 | 共用字段feeFen没有区分业务类型 | 两端按kind显示“办卡/补卡报价”，会员单独显示会员费用；新增回归防止向农户收费的歧义 |

早期测试脚本的错误路径`/farm-preview`、隐藏侧栏按钮和重复文字定位已纠正，不当成系统故障。开发期间修改源码造成的HMR暂态失败已在代码稳定后完整复测；最终矩阵无白屏、错误覆盖层或页面JS异常。

## 实测结果

- API：37/37通过，包含11组新增主链与异常链，库存竞争在一个用例内重复8轮。
- 网页：340/340单元及回归测试通过；TypeScript和backend-mode生产构建通过。
- 小程序源码：58/58单元及回归测试通过。
- 双引擎只读兼容性：274/274检查通过，含20个工作台模块的六档宽度、日期填写、身份切换、只读历史弹窗、Escape恢复滚动、菜单键盘、凭据CORS、公共页面及小程序预览。云农场检查仅覆盖“尚未实接”的边界页面。
- 双引擎真实UI流程：网页新办卡→管理员审核/云端登记→小程序读取同一申请；网页库存发布→买方采购→卖方确认/登记发货→买方独立验收→小程序读取同一交接历史，均通过。没有提交真实付款或合同。
- 数据库运行权限、迁移与标准/审计/绑定/交接/方案不可变性检查通过。

测试截图位于浏览器脚本输出的临时目录，可能被系统清理；脚本保存在`backend/test/browser-compat.cjs`、`backend/test/browser-workflow.cjs`，可重新生成。API新测试对象信息不含密码与令牌。

实际执行：`npm test`（admin-web）；`node --test miniapp/tests/*.test.cjs`；`node --test --test-concurrency=1 test/*.test.mjs`（backend）；`VITE_DATA_MODE=backend npm run build`；Java21/Maven离线构建；`LocalDatabaseCheck.java`；`test/browser-compat.cjs`和`test/browser-workflow.cjs`。API/浏览器密码仅来自本地环境，WebKit缓存放临时目录，不修改Safari设置或项目依赖。

## 资金及生产上线待验收

会员收费方案只到awaiting_payment；卡费用固定10000分报价，不是收款。商户录入为pending，不代表支付侧核验。分账池是商户侧服务收入计算计划，不从种植户扣平台服务费；比率明确配置，金额余数归中心。计划状态blocked_external、externalExecuted=false；执行返回503。

真实分账需要已支付交易、服务商/特约商户开通和接收关系、签名与通知验签、可分账余额/限额、异步接收方结果、退款回退及对账。官方依据：[请求分账](https://pay.wechatpay.cn/doc/v3/partner/4012690683)、[接入准备](https://pay.wechatpay.cn/doc/v3/partner/4012072589)。不能将HTTP受理成功等同资金全部到账。
