# 商户与分账：管理后台专用

本轮用户已确认有服务商号及中心特约商户号；未提供号值、证书或密钥，本轮不进行真实绑定、付款、分账或退款。UI在管理后台“商家服务与会员”页下，含商户绑定、分账测算、对账退款；小程序及主体工作台没有财务管理入口。

## 主体和收款

平台乡桥农业有限公司作为微信支付服务商；各农事中心作为特约商户。订单应绑定实际销售主体及对应商户，中心订单不自动归集到平台再转出。跨中心购物拆订单；平台自营商品按实际销售主体路由。商家信息权益收费与微信支付商户绑定是不同概念；一个业务账号的多种身份不等于有多个支付商户或财务权限。

服务费须双方合同、接收方授权与中心批准额度共同确认；不默认10%或任何统一分账比例。农户记录服务平台费0，卡片办卡/补卡100元为单独价款，不默认从农户售货款扣平台费。实际费用、开票、交易手续费承担及税务处理须合同和财务专业核定。

## 计算与异步状态

微信分账提交金额而不是比例；由服务器转为整数分，并检查每笔支付单的累计分账上限。收到分账不代表自动提现；退款发生在分账后，应核实接收方回退权限及相应回退、退款处理。依据[微信支付服务商分账常见问题](https://pay.wechatpay.cn/doc/v3/partner/4014547107)。

真实执行还需核对剩余可分金额、交易手续费、退款及既往分账，不能直接使用“订单金额－平台费”作为实际净结算款。当前UI仅支持本地算术参考，不产生有效规则或支付指令。

正式状态：合同与规则独立审批 → 支付通知验签与入账 → 可分额度核对 → 分账请求受理 → 异步查询确认 → 余款解冻核对 → 渠道对账。请求受理≠成功，分账≠提现，退款≠回退完成；失败、部分成功、重复回调、退款和争议均保留台账。

## 服务端交接对象

account、organization、membership、business_role、finance_grant分别建模；财务授权由平台和中心管理流程单独签发。操作主体和审核人独立，自然人跨多个账号的自审风险也必须阻断。

对象包括：ProviderConfig、CenterMerchantBinding、AuthorizedReceiver、VersionedSharingRule、PaymentOrder、PaymentCallback、SharingOrder、SharingReceiverResult、UnfreezeRecord、ReturnOrder、RefundOrder、ReconciliationDifference、FinanceAudit。支付单锁定sub_mchid、真实销售主体与规则快照；不可事后改主体掩盖流向。

每种业务单使用独立幂等编号；回调验签、解密及重复通知处理在服务端，金额必须整数分。密钥和证书不入前端或小程序。平台财务只按授予范围处理，各中心财务仅本中心；审核、申请、执行权限拆分，审计不可覆盖。

上线需逐项核验产品权限、服务商与特约商户对应关系、AppID授权、接收方、最大可分比例、通知地址、结算账户、合同和退款权限。接入前再次阅读[请求分账](https://pay.wechatpay.cn/doc/v3/partner/4012690683)与[添加接收方](https://pay.wechatpay.cn/doc/v3/partner/4012690944)官方规范。本稿不是已获产品权限或资金合规证明。
