# 乡桥网页与小程序递归审查 V2

日期：2026-10-06（北京时间）。依据仓库代码、现有业务设想和本轮新增模块进行有限范围复查，不是生产上线、真实交易、政府认证或硬件验收证明。

## 一、核心结论

保留五个网站入口、一个多身份小程序和一套统一业务底座。按业务模块划分，不为每个角色、每个区县复制一套独立后台。当前页面和原型可验证交互，可信业务后端仍是生产上线的核心缺口。

业务身份必须可按产区配置：固定的是经过验证的流程模板与安全规则，不是“只能有11或12个角色”。葡萄修剪队、套袋队、茶园管护队等可复用农服履约；确需独立准入或责任范围时建立新的身份定义。修剪、套袋、采摘也可以是服务能力标签，不必全部拆成需要反复切换的身份。

本轮区分三类状态：

1. **源代码已实现**：页面、筛选、草稿、演示状态机与本机回归测试。
2. **只在本机模拟**：管理员审批、中心筹备、新闻发布、社交配置、第三方接入与日志。
3. **待服务端/实物接入**：真实登录、对象权限、多中心隔离、硬件、库存事务、支付、报送、跨端工单和生产消息。

## 二、递归方法与停止条件

每项功能依次拆解：业务目标 → 参与者 → 入口页面 → 业务对象 → 状态转换 → 授权/证据 → 异常和重试 → 上下游回查。

每层复查正常、失败、撤回、重复提交、并发、越权六类路径。发现下层规则与上层承诺冲突，就回查上层：例如“后台保存社交链接”不能推导为“不同域名官网已更新”。同一对象、权限或状态的矛盾被记录并明确处置后结束本轮，不宣称穷尽全部缺陷。

## 五、身份与多中心：必须分开的对象

### 1. 身份结构

- Account：登录的人；与微信/手机号等经过核验的凭证关联。
- BusinessSubject：农户、合作社、公司、服务队等业务主体。
- Membership：某账号加入某主体的成员关系。
- BusinessIdentityDefinition：中心/产区的身份目录定义，包含稳定ID、展示名、基础流程模板、模块能力、准入标准和版本。
- BusinessIdentityGrant：某成员已获审核的具体身份；不是目录保存后自动产生。
- AdministrativeGrant：平台、县域、乡镇后台岗位和对象操作权限。
- Delegation：子女代办等有范围、期限、撤销状态的授权，不能代替无限权限角色。

身份名称不是鉴权字段。服务端核验成员、身份授权、中心范围和对象归属；列表、详情、文件、导出、消息和写操作必须一致。当前小程序和网页固定角色清单需要迁移到共享目录，但保留模板规则，不能把任意role字符串作为授权。

### 2. 区县组织结构

```text
乡桥农业有限公司（平台）
└─ 区县服务运营主体 / 农事中心
   ├─ 福安市乡桥农事综合服务有限公司（福安试点规划）
   ├─ 其他区县中心（需审核后建立）
   └─ 所属乡镇服务站
```

分公司、独立公司、合作运营主体和乡镇站点分开记录。目录层级不证明法定股权/分公司关系，也不自动确定谁签约、开票、收款或负责售后。正式启用须核对法定主体、辖区、品牌授权、人员、数据范围、商户绑定和运营责任。

多中心复用代码与流程模板，不复制农户记录、库存、管理员授权或资金。全国汇总只使用有授权且经脱敏的指标。跨中心协作通过受控协作对象表达，不能靠前端countyCode或中心选择器切换数据库获得权限。

### 3. 当前新增目录能力

后台`/settings/identities`可按产区新增业务身份草案、选择共用模板、填写准入要求和导出目录JSON。保存只产生草案，不会给用户授权；也未自动同步到各域名或小程序。正式端应统一提供已发布目录查询、目录变更审核、身份申请与授权接口。

## 七、业务闭环递归验收矩阵

| 闭环 | 正常路径 | 必须阻断 / 回查 |
| --- | --- | --- |
| 加入与身份 | 目录→申请→证据核验→有效成员/身份 | 目录草案不开放身份，拒绝/撤销后不能用旧缓存进入 |
| 地块产季 | 边界→作物→产季→成熟预测 | 作物变更要照片、视频、版本与审核，旧供货/预测待复核 |
| 卡与同步 | 按键原始事件→手机暂存→服务端持久化→回执 | 无持久化不清设备；定位失败不造坐标，重传不重复入账 |
| 农资 | 购买/退货凭据→实际施用确认→农事关联 | 买入不等于施用；刷NFC不等于付款、验收或数据全量授权 |
| 农服农机植保 | 委托→接单→作业留证→完工→独立验收 | 同人切换角色/多个账号不得自审；植保专业字段与安全间隔独立 |
| 检测 | 委托→采样封样→检测报告→独立核验→建议 | 机构资质、报告真实性与建议版本分别校验，不冒充法定认证 |
| 成本 | 确认人天+实际施用+服务/其他成本+行情→版本化估算 | 按键非人天；现金/完整成本分开；×1.35是参考加价，不是强制收购价 |
| 产销库存 | 批次→货权/保管权→预留→交接出库 | 并发超卖、预留超期释放、加工数量平衡、退货/损耗要账本 |
| 消费 | 授权农场→明确方案→意向→真实订单/合同→履约售后 | 假直播、未确定价格、不真实库存、减产及退款不能绕过 |
| 财务 | 正确中心商户→支付确认→分账→回退/退款→对账 | 客服/普通角色不能执行；验签、幂等、金额守恒及独立审核 |
| 报送 | 授权→预检→提交→受理回执→外部审核结果 | 本地导出、HTTP成功或模拟按钮不等于“一品一码”审核通过 |
| 帮助 | 问题→受理→分派→答复→用户确认/重开 | 回访意向不是通话，中心间隐私隔离；客服不能自行改账/验收 |

## 八、主要发现与优先级

### P0：生产开放前必须完成

1. **后端仍是骨架**：补统一账号、主体成员、多身份、管理员权限与对象授权，再接真实业务；五表不足以支撑新逻辑。
2. **多中心尚未有可信租户隔离**：当前fuan和中心列表是模拟配置，不能复用成全国数据访问权限。新增中心不是注册公司或开通支付商户。
3. **动态身份只到目录草案**：Web11角色和小程序12角色的固定枚举尚未读取已发布目录；业务模板、身份定义、授权关系必须拆开。
4. **硬件与交易账本尚未接入**：BLE/NFC/GNSS、设备回执、库存事务、真实合同、支付分账和第三方回执都不可用UI成功提示代替。
5. **跨域/跨端不存在可信写入联动**：新闻、社交、工单、消息、地块与财务不能靠各端localStorage/wxStorage保持一致。

### P1：进入联调前统一

6. **Web消费身份与小程序目录不一致**：小程序已有消费者身份，Web产业工作台只列11业务角色，农场为独立访客演示。真实产品需同一Account/Membership支持生产与消费，不各建账号。
7. **成本表单口径不完全一致**：Web有days、inputs、services、other等，小程序通用表单没有独立服务成本科目。共享CostSnapshot科目/单位/缺项规则，避免服务费漏计或重复合并。
8. **退出清理规则不一致**：Web清当前账号；小程序`session.logout()`清全部演示前缀，登录另一个演示账号也调用logout。正式端应明确共享设备安全规则与当前账号边界，不误删其他账号草稿。
9. **小程序通用业务页旧上下文检查仅比较identity.id**：当前示例ID独立；真实授权必须同时核验Account、Membership和RoleGrant。不要让跨账号同主体身份碰撞绕过旧页校验。
10. **管理会话储存容错不足**：AuthContext直接读取/解析localStorage，损坏JSON或储存被禁用可能阻断入口。新模块的独立储存容错测试不证明整个登录外壳安全。
11. **原型对象作用域仍依赖样例**：Web有姓名/固定角色筛选；小程序通用模块多数为表单草稿。正式端以稳定Subject/Plot/Order ID和服务端对象授权替代名字比较。

P1是本轮审查发现，不代表本次已改动这些历史模块。新增模块中的非法日期、未知岗位、新闻编辑参与者自审与弹窗内错误不可见等问题已在本轮代码中修正。

## 十、推进顺序与交付门槛

1. 冻结共享对象、状态、金额/数量/工时/时间单位、错误码和版本契约；先统一身份、中心、目录、上下文及附件授权。
2. 实现真实账号/成员/授权，统一Web和小程序的身份目录与对象权限，完成跨中心越权与撤销测试。
3. 选择福安葡萄试点的一条“地块→卡/农事→服务→独立验收→成本→供货/报送”闭环联调；不要同时假上线全部模块。
4. 接统一新闻、社交账号、日志和帮助工单后端，再增加库存事务、真实农场设备和经过核验的交易/财务接口。
5. 用小范围真实样本与20个工程样机验收，再扩大1000张、10000张；承诺以实际证据为准。
